# Initial long-run detector decision

Decision date: 2026-09-05. Scope: one bounded first learned baseline on the
existing 12 GB Vast GPU, at most eight GPU-hours for the campaign including
smokes and GPU evaluation. This is a proposed recipe, not an executed training
result. The launched configuration and run ledger are authoritative if the
coordinator changes a parameter after the smoke test.

## Recommendation

Build a small 3D convolutional point detector from scratch. Supervise a compact
Gaussian neighborhood of each known cell center, use a separate, low-weight loss
on conservative image-derived dark background, and give every other voxel zero
loss weight. Keep the existing adjacent-frame linker and physical NMS fixed for
the first comparison. Preserve the classical fallback.

This is an intentionally small feasibility experiment. Its scientific question
is whether transferable local appearance improves detection recall and density
on the other embryo. A longer falling-loss curve alone cannot answer that.
Neither local supervision nor darkness establishes complete cell annotation.

Do not adopt new pretrained weights for this run. Existing FOCUS-3D and public
point-detector leads remain useful next experiments, but their training
membership, artifact terms and inference cost were not established by this
bounded research pass. See [the earlier evidence ledger](alpha-2026-09-05.md).

## Compare supervision choices

| Choice | Advantage | Failure mode | Verdict |
|---|---|---|---|
| Dense Gaussian map with zeros everywhere else | Simple detector objective | Most unlabeled real cells become negatives | Reject. |
| Positive points only, all remaining voxels ignored | Does not invent negative cells | Constant/high predictions are insufficiently constrained; sharp localization is not identifiable | Diagnostic ablation, not the sole long-run objective. |
| Gaussian support with an outer negative annulus | Teaches local shape | Neighboring unlabeled centers can lie in the annulus; sparse nearest-neighbor labels do not prove an empty shell | Do not use a large zero-target ring. |
| Compact positive Gaussian support plus conservative dark background | Adds contrast without declaring every unlabeled location negative; small implementation | Dim cells can be mislabeled; bright non-cell structures remain unconstrained; output scores are not calibrated probabilities | Recommended provisional baseline, with audited masks and density checks. |
| nnPU classifier on existing candidate patches | Uses positives and unknown proposals without ordinary negative labels | Class prior and representative-positive assumptions are uncertain; cannot recover cells absent from proposals | Strong next bounded comparison if this detector overproduces. |

## Concrete initial tensor and target contract

1. Decode exactly one uint16 `(Z,Y,X)` frame at a time. Downsample only XY by
   four with a specified antialiasing/block-average operation. The common scale
   becomes `(1.625,1.625,1.625)` micrometers. Check the actual metadata; never
   assume these values when a volume declares otherwise.
2. Preserve the coordinate convention exactly. For 4-by-4 block means with
   center-aligned coordinates, `x_original = 4*x_small + 1.5` and likewise for Y.
   Z is unchanged. Test a known synthetic point through target generation and
   inference inversion. Nearest-grid rounding needs boundary clipping.
3. Use per-frame robust intensity scaling to `[0,1]`, for example quantiles 1
   and 99.8 followed by clipping, with an explicit constant-frame rule. This is
   a frozen per-image transformation, not fitted using held-out labels. Build
   the background mask before stochastic intensity augmentation.
4. Input batches have shape `(B,1,D,H,W)` float32 or mixed precision. A starting
   crop is `(32,48,48)` at the downsampled scale and batch size four, subject to
   measured memory. A two-downsampling-level U-Net with widths `(16,32,64)`,
   GroupNorm and one output logit is sufficient for the first run. A still
   smaller fully convolutional network is acceptable if the smoke shows a
   runtime advantage; log exact parameters and receptive field.
5. For each voxel let `d` be physical distance to the nearest annotated point,
   retaining fractional downsampled point coordinates. Set
   `H = exp(-d*d/(2*sigma*sigma))`, initially `sigma=1.625` micrometers, and
   `M_pos = (d <= 1.625 micrometers)`. Take a maximum over overlapping point
   targets, not a sum. This deliberately supervises only the positive core,
   with target at least `exp(-0.5)`, not a broad negative annulus. These radii
   are project starting assumptions and can underfit localization.
6. Define a candidate dark mask where the maximum normalized image intensity
   in a 3-by-3-by-3 neighborhood is at most `0.05`. Exclude every voxel within
   `6.5` micrometers of any annotation. The remaining `M_bg` is pseudo-background,
   not ground truth. An empty mask contributes zero background loss; never
   silently replace it with random unlabeled voxels.
7. For `P=sigmoid(logit)`, start with separately normalized losses:
   `L = mean_M_pos((P-H)^2) + 0.05*mean_M_bg(P^2)`.
   Explicitly zero the weight elsewhere. Separate normalization prevents dark
   voxel counts from overwhelming the positives. The background coefficient
   is a heuristic and not borrowed performance evidence.

The final negative mask must never intersect positive support. Also report the
fraction of annotated centers satisfying the intensity-only darkness rule
BEFORE exclusion. Exclusion guarantees zero final overlap by construction, so
zero final overlap alone is not evidence that the heuristic is correct.
Inspect the lowest-intensity labeled-center examples. If many satisfy the raw
dark rule, reject or tighten that rule before scaling; do not hide the issue
by counting only the post-exclusion mask.

Log positive-mask fraction, background-mask fraction, unknown fraction and
labeled-center prediction quantiles by training clip. A mask unit test should
place a bright unlabeled synthetic cell outside positive support and verify
zero loss gradient there. Another test should verify that empty annotations
do not turn a whole frame into negative supervision.

## Sampling and augmentation

Choose clips uniformly first, then frames uniformly, rather than sampling
uniformly from all annotated nodes. This limits domination by dense or long
tracks. Sample half the crops around a randomly selected known center with
random offset and half uniformly from the frame. For a selected frame without
labels, retain only conservative background supervision or resample with a
bounded, explicitly logged policy. Never treat no annotation as no cells.

Use XY right-angle rotations and flips, consistent image/point/crop transforms,
moderate brightness/gamma perturbations and small noise. Do not permute Z with
XY merely because resampling made voxel sizes equal: the imaging PSF can remain
anisotropic. Generate several independent crops from a bounded frame cache to
amortize Zarr decoding, but track unique clip/frame coverage. Cache quotas must
respect the downloader's disk reserve; RAM caches should also be bounded.

## Selection, early stopping and budget

The frozen outer folds remain `44b6 -> 6bba` and `6bba -> 44b6`. Reserve a fixed
hash-selected approximately 10% of clips inside each training embryo for
development. All frames of a development clip remain together and stay out of
gradient updates. Nearby fields of view inside one embryo may overlap, so this
development score is only a training control; it is not independent evidence
of embryo generalization.

Select checkpoint and detection threshold only on this inner development set.
Use a small predefined threshold grid, for example `0.35,0.5,0.65,0.8`, and fix
the existing NMS/linking parameters. Do not use the opposite embryo's counts,
estimated totals or scores to tune the detector. After freezing a candidate,
evaluate the complete other embryo once. Repeated opposite-embryo checkpoint
selection must be described as validation-driven model selection, not an
untouched holdout. With only two embryos, even clean outer scores have limited
population-level precision.

Coordinator's scheduling ceiling: up to 2.5 hours training per direction,
one hour for an all-training-data refit under the frozen selected recipe, and
two hours shared GPU smoke/evaluation/recovery reserve. The refit may use both
embryos after outer evaluation but has no remaining independent local holdout;
its training loss must not be reported as validation. Freeze its duration and
threshold before refitting. The coordinator should adjust downward from
measured throughput; eight GPU-hours is a ceiling, not a required utilization
target. CPU classical scoring can run alongside the single GPU training owner
if measured CPU/RAM/I/O contention is acceptable. It can extend wall time and
must have its own recorded deadline.

Use AdamW, learning rate `3e-4`, weight decay `1e-4`, gradient clipping at 1 and
mixed precision after the smoke confirms finite gradients. Fix seed, optimizer
and schedule before the long run. Define a reporting epoch as 500 sampled
updates, not a pass over every frame. Use an explicit upper step count and
monotonic wall-clock deadline. Report optimizer steps, samples and unique
frames, not just an ambiguous epoch count.

Run development diagnostics about every 15 minutes, with official complete-
clip scoring at a measured cadence that fits the budget. A conservative
initial early-stop rule is no official development score gain of at least
0.002 for four evaluations after at least 45 minutes, always retaining best,
latest and previous. These numbers are operational defaults, not established
convergence facts. If scoring is expensive, use fewer scheduled evaluations
and a fixed duration rather than falsely declaring stagnation from training
loss. Save atomic resume checkpoints at most ten minutes apart independently
of evaluation, and verify interrupted/resumed updates before the long run.

Stop immediately on nonfinite loss/gradients, invalid graphs, corrupted data,
failed checkpoints or exhausted budget. Increasing prediction density with
falling training loss is a diagnostic warning. Compare predicted/estimated
total counts and sparse-node recall against the classical path on the SAME
complete development clips. A count estimate is noisy; it should not be used
as a per-frame exact target or silently imposed as a hard detection cap.

## Required evidence before promotion

Use the pinned official metric, including adjusted and raw edge Jaccard,
division Jaccard, edge/division TP/FP/FN, node recall and predicted/estimated
node totals. Save per-clip values, official aggregate definition and runtime.
Compare both outer directions to the identical classical configuration. The
four example test clips are engineering checks only. Full-clip all-frame
evaluation is required to assess temporal links; disjoint sampled frames do
not form a valid tracking benchmark.

Retain source/config/split hashes, environment, masks' audit summary, seed,
throughput, peak VRAM, checkpoint hashes, actual stop reason and durable backup
readback. Frozen from-scratch provenance is a benefit of this first baseline,
but successful training is not evidence of competitive tracking. Submit only
after the coordinator's offline Kaggle rehearsal and output gates pass.
